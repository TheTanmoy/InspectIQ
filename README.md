# InspectIQ — AI Quality Inspection Report Generator
**Team Prompt Syndicates · AI Friday Season 3**

InspectIQ turns sensor, camera and manual-check data from a 3-line automotive parts plant into **standardized,
compliance-checked quality inspection reports in seconds**. Code computes every number; the AI writes the words;
guardrails check the AI; humans review and approve.

> All data in this project is **synthetic** (generated by `backend/synthetic/generate.py`).

---

## Quick start (Windows, VS Code terminal — no extensions needed)

**Prerequisites:** Python **3.12** (3.15 is too new for some packages) and Node.js 18+.

```bash
# Terminal 1 - backend
cd backend
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
uvicorn app.main:app --reload --port 8000
```

```bash
# Terminal 2 - frontend
cd frontend
npm install          # if PowerShell blocks scripts: npm.cmd install
npm run dev          # then open http://localhost:5173
```

On first start the backend generates the synthetic data (about 1 second) and creates `backend/inspectiq.db`.
API docs (Swagger): **http://localhost:8000/docs**

### Plug in the provided LLM
Edit `backend/.env`, then **restart the backend** (`.env` is read only at startup):

| Organisers give you… | Set |
|---|---|
| OpenAI-style endpoint (most common) | `LLM_PROVIDER=openai`, `LLM_BASE_URL=<url>/v1`, `LLM_API_KEY`, `LLM_MODEL` |
| Azure OpenAI | `LLM_PROVIDER=azure`, `LLM_BASE_URL=https://<res>.openai.azure.com`, `LLM_MODEL=<deployment>` |
| Anthropic | `LLM_PROVIDER=anthropic`, `LLM_MODEL=<model id>` |
| Gemini | `LLM_PROVIDER=gemini`, `LLM_MODEL=gemini-…` |

If the model accepts images, set `LLM_VISION=true` and defect photos are sent with the report prompt.
Without a key the app runs in **template mode**: reports are written from the computed facts by a deterministic
template, so every screen works before you have the key.

## What it does (mapped to the problem statement)

| Requirement | InspectIQ |
|---|---|
| AI-generated defect descriptions | LLM describes each defect group from camera detections, measurements and notes (plus photos if vision is on) |
| Standardized report formatting | Fixed template `QIR-STD-01`, standard defect codes; messy notes ("scrach", "porous spot") mapped to codes |
| Interactive editing | Section editor, AI rewrite with accept/reject, dispositions, detection verification, version history |
| Defect trend dashboards | KPIs, daily trend per line, Pareto, SPC chart with limits, Cpk table, shift comparison |
| Real-time integration with inspection APIs | `/api/inspection/*` data API + live simulator; reports for in-progress lots; swap to a real API with `INSPECTION_SOURCE=http://…` |
| Regulatory compliance | Editable, versioned rulebook (12 synthetic rules); score per report; blocking rules stop approval |
| Reduce report time / improve accuracy | Timer on every report; every AI number verified against computed facts |
| Role-based access | 4 roles, permissions enforced in the API and reflected in the UI |
| Audit logging | Every login, edit (before/after), workflow step, rule change and AI call |
| Basic error handling | Friendly errors for every failure; LLM fallback; rate limits; broken rules never crash |
| No model retraining | Prompting + grounding only |

### Planted in the synthetic data (so the demo has something to find)
1. **Porosity spike on L1 night shift (C)** after a mold insert change 12 days ago.
2. **Rod diameter drift on L3 ST2** towards the upper limit (tool wear), Cpk falling below 1.
3. **Gauge G-201 calibration expired** → L2 reports are blocked by compliance rule R-005.
4. **Raw-material heat ML-L3-0xx on L3** (supplier certificate: sulphur 0.041% vs max 0.035%, inclusion rating 2.1 vs max 1.5,
   accepted under deviation 9 days ago) raises **pitting on every shift** - a material cause, which the dashboard separates from
   shift/process causes. Every production lot is traced to its material lot (`materials.csv`); rule R-013 checks the certificate.
5. A **prompt-injection** hidden in an inspector note (latest L1 shift C lot).
5. **Personal data** (name, email, phone) in an inspector note (latest L2 lot).
6. A **critical crack** (latest L2 lot) → escalation + containment rule R-003.

## LLM guardrails (`backend/app/core/guardrails.py`)

**Before the call:** prompt-injection removal · PII masking (names → IDs, emails, phones) · untrusted data fenced
in `<untrusted_data>` · prompt size cap · assistant topic + injection check · per-user rate limit.

**After the call:** JSON schema validation (pydantic) · **number verification** (every number must exist in the
computed facts) · defect codes from the approved list only · fixed severity rules (crack = always critical) ·
cited part serials must exist · absolute claims removed ("fully compliant", "zero defects") · low-confidence
detections flagged for human verification · AI never decides accept/reject.

**Operations:** low temperature for reports (0.1) · template fallback if the LLM fails · provider safety-filter
errors handled · every AI call logged (model, prompt version, latency, guardrail results) · reports labelled
"AI-generated draft – pending human review" until approved.

## Compliance rulebook (`backend/app/services/compliance.py`)
Rules are **data**, not code: each has a `type` (deadline, traceability, critical_escalation, disposition_required,
calibration_valid, sampling_plan, approval, required_sections, cpk_threshold, ai_advisory, low_confidence_review,
threshold) and editable `params`, severity, blocking flag and on/off switch. Editing creates a new rule version and
a new rulebook version, is audit-logged, and the UI shows which open reports changed outcome.
Clause references are placeholders "modelled on IATF 16949 / ISO 9001-style requirements" — verify before real use.

## Useful commands
```bash
cd backend
python -m pytest -q                       # run tests
python -m synthetic.generate              # regenerate synthetic data (then delete inspectiq.db and restart)
```
**Reset the demo:** stop the backend, delete `backend/inspectiq.db` and `backend/data/`, start again.

**Single-port demo (recommended for judging):** `cd frontend && npm run build`, then start the backend — the app is
served at http://localhost:8000.

## Troubleshooting
| Problem | Fix |
|---|---|
| `pip install` fails building pandas/pydantic | Use Python 3.12: `py -3.12 -m venv .venv` |
| `npm` not recognized | Install Node.js LTS, restart VS Code |
| "running scripts is disabled" | Use `npm.cmd install` / `npm.cmd run dev` |
| Logged out after restart | Set `SECRET_KEY` in `.env` |
| LLM errors | Click the status in the sidebar, check `/api/health`, check `.env`, restart backend |
| Corporate proxy SSL errors | `VERIFY_SSL=false` in `.env` (only if required) |
